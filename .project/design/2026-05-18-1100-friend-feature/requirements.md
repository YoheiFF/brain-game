# 要件定義書: フレンド機能

## 1. 背景・目的

BrainGame は現在、全ユーザー共通のグローバルランキングのみを提供している。  
フレンド機能を追加することで、知人同士の競争を促し、エンゲージメントおよびリテンション向上を図る。

---

## 2. スコープ

### 対象プラットフォーム
- Web（ブラウザ）: `https://brain-game-opal.vercel.app`
- Android アプリ: Capacitor v8 WebView

### 対象ユーザー
- BrainGame の全ユーザー（ニックネーム登録済み）

---

## 3. ユーザーストーリー

| # | ストーリー | 優先度 |
|---|---|---|
| US-01 | ユーザーとして、自分のフレンドコード（6文字）を確認したい | 必須 |
| US-02 | ユーザーとして、フレンドコードを LINE でシェアしてフレンドを招待したい | 必須 |
| US-03 | ユーザーとして、相手のフレンドコードを入力してフレンド申請を送りたい | 必須 |
| US-04 | ユーザーとして、届いたフレンド申請を承認または拒否したい | 必須 |
| US-05 | ユーザーとして、フレンド一覧を確認したい | 必須 |
| US-06 | ユーザーとして、フレンドのみのランキングを見たい | 必須 |
| US-07 | ユーザーとして、URL の ?code= パラメータ付きリンクを踏んだら自動でコードが入力されてほしい | 必須 |
| US-08 | ユーザーとして、フレンドコードをクリップボードにコピーしたい | 推奨 |
| US-09 | ユーザーとして、Web Share API（ネイティブシェアシート）でシェアしたい | 推奨 |

---

## 4. 機能要件

### 4-1. フレンドコード

- 6文字の大文字英数字（文字セット: `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`、視覚的混同文字 0/O/1/I/l を除外）
- `crypto.getRandomValues()` を使用して生成
- DB の UNIQUE 制約で衝突した場合、最大5回リトライして生成
- ユーザー初回登録時（`upsertUser` の Server Action 呼び出しタイミング）に自動生成・保存
- 既にコードを持つユーザーは再生成しない
- 大文字小文字を区別しない検索（フレンド申請時は `UPPER()` で正規化）

### 4-2. フレンド申請フロー

1. 申請者: フレンドコードを入力 → `POST /api/friends/request`
2. サーバー: フレンドコードでユーザーを検索 → `friendships` レコードを `status=pending` で作成
3. 受信者: フレンド管理ページで申請一覧を確認（`GET /api/friends/pending`）
4. 受信者: 承認または拒否 → `POST /api/friends/respond`
5. 承認時: `status=accepted` に更新 → 双方向フレンド関係が成立
6. 拒否時: `status` を `rejected` に更新（レコードは削除せず重複申請防止に活用）

### 4-3. フレンド一覧

- `status=accepted` かつ `requester_id=自分 OR addressee_id=自分` で取得
- フレンド上限: 50人
- 表示項目: ニックネーム、フレンドコード（一覧には不要）

### 4-4. フレンドランキング

- フレンド（status=accepted）のユーザー ID リスト ＋ 自分の ID を取得
- 既存の `getRankingsFromDb()` と同等のロジックで、対象ユーザーを絞ったランキングを生成
- ゲーム別ランキング・総合ランキングともに表示
- フレンドが0人の場合は「フレンドを追加しよう」の空状態を表示

### 4-5. LINE シェア

- `https://line.me/R/share?text=<urlencoded>` を使用
- シェアテキスト:
  ```
  🧠 BrainGameで友達になろう！
  フレンドコード: {code}
  https://brain-game-opal.vercel.app/add-friend?code={code}
  ```
- `navigator.share` が利用可能な場合はネイティブシェアシートを優先使用
- `navigator.share` が使えない場合は LINE シェアボタンをフォールバックとして表示

### 4-6. UI 配置

- ホーム画面（`app/page.tsx`）の右上リンクボタン群に「👥 フレンド」ボタンを追加
- 新規ページ:
  - `/friends` - フレンド管理ページ（コード表示・シェア・申請・承認・一覧）
  - `/add-friend` - フレンドコード入力ページ（`?code=xxx` パラメータを受け取り自動入力）
  - `/friends/ranking` - フレンドランキングページ

---

## 5. 非機能要件

| カテゴリ | 要件 |
|---|---|
| セキュリティ | userId は UUID、クライアント認証なし（既存の制約と同レベル） |
| セキュリティ | フレンドコード検索 API はフレンドコード→userId のマッピングを直接公開しない |
| CORS | 既存の `ALLOWED_ORIGINS`（`capacitor://localhost`, `http://localhost`）パターンを全エンドポイントに踏襲 |
| パフォーマンス | フレンドランキング API は `Promise.all` で複数クエリを並列実行 |
| 可用性 | DBマイグレーションは `IF NOT EXISTS` / 冪等な実装で再実行可能 |
| 互換性 | 既存の `SyncResponse` 型・`/api/sync` エンドポイントは変更しない |

---

## 6. 制約事項

- 認証機構なし: userId の正当性はクライアントが `localStorage` から渡す UUID のみ
- プッシュ通知基盤なし: フレンド申請通知は「申請が届いています」バナーのポーリングで代替
- Capacitor: `window.open(lineShareUrl, '_blank')` で動作（`@capacitor/browser` 不要）
- Turso/libSQL: `ALTER TABLE ADD COLUMN` は SQLite 互換でサポート済み
